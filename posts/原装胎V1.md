上一版（原装胎 V0）的环岛能进能出，但出环之后 1～2 秒，车会突然第二次“入环”，猛地满差速打一把，然后冲出赛道。更糟的是第一次出环失败、超时退出的那一次，车会在环里原地转圈。

我一开始以为是门限太松。把 92 调高，没用；调低，变成直道误触发。后来把四个归一化值打到屏幕上盯着看，才明白问题根本不在门限。

环岛出口的磁场，和入口长得一模一样。

入口是“两个横电感满、两个竖电感空”，因为车头正对着一圈线圈的缺口。出口呢？车从缺口出去，车头又一次正对着缺口，四个电感又一次是“横满竖空”。

光靠空间特征，入口和出口是不可区分的。想让状态机不重复触发，只能引入时间：刚出环的一段时间里，不管看到什么，都不许再进。

这一版唯一的新增机制，就是这个冷却。

```c


uint16 ring_cooldown = 0;    /* 冷却计时器，5 ms 一拍 */

/* 状态 0：冷却没走完只做减法，不做判断 */
if (ring_cooldown > 0)
{
    ring_cooldown--;
}
else
{
    if (Adc_LEFT1_Value > 80.0f && Adc_RIGHT2_Value > 80.0f &&
        Adc_LEFT2_Value < 15.0f && Adc_RIGHT1_Value < 15.0f)
    {
        ring_timer++;
        if (ring_timer > 2) { ring_state = 1; ring_timer = 0; }
    }
    else ring_timer = 0;
}
300 × 5 ms = 1.5 秒。
```
这个数不是拍脑袋的：出环到跑完缺口那段直道大概 1 秒出头，留 0.5 秒余量。太快会二次触发，太慢会漏掉真正的下一个环岛。如果赛道上有两个环，这个值就是两个环之间的最小间隔。

出环的时候把它装满：

```c


else if (ring_state == 3)                  /* 出环回正 */
{
    ring_timer++;
    turn_out = 0;                          /* 两轮同速冲出去 */

    if (ring_timer > 100)                  /* 500 ms 直行 */
    {
        ring_state = 0;
        ring_timer = 0;
        ring_cooldown = 300;               /* 1.5 s 内绝不再进环岛 */
    }
}
```
顺带把门限也放宽了：横的 92 → 80，竖的 5 → 15，连续确认 4 拍 → 3 拍。

原因很实际：92 是某天满电、电感离地 15 mm 时测出来的峰值。电池掉到 7.4 V 以下，或者车重压得多一点，峰值可能只有 85，这时候上一版就进不去环岛了。而且失败方式特别气人：在环岛口减速、犹豫，然后被直道拉走。

放宽门限的代价是直道更容易误触发，所以消抖反过来从 4 拍收到 3 拍。一宽一紧，用“更快地确认”换“更低的门限”。实测这个组合比“门限严 + 消抖松”稳，因为误触发主要来自一瞬间的尖峰，而进不去环岛是因为峰值本来就到不了。

还有一个更隐蔽的问题：超时。

上一版是这么写的：

```c


if (ring_timer > 600) ring_state = 0;   /* 3 秒还没出去，直接回状态 0 */
```
看起来合理，实际上是最坏的失败方式：车还在环里，状态被清成“找入环口”，下一拍立刻又看到“横满竖空”，于是重新入环、再打一把满差速。车就在环里反复抽搐。

这一版改成切到状态 3：

```c


if (ring_timer > 600) { ring_state = 3; ring_timer = 0; }
```
状态 3 是出环回正：差速清零，直行 500 ms，然后才回状态 0 并上冷却。哪怕车其实还在环里，这一步也能把它掰回直道方向，而不是原地打角。

超时保护要做的是“执行一个安全的退出动作”，不是“把变量清零”。清零只是让状态好看，车并不会因此离开环岛。

最后把出环直行从 100 ms 拉到 500 ms。原来 100 ms 太短，经常刚出缺口就被环岛的余磁拽回去。代价是这半秒完全不修正，如果出环时车头本来就歪，会把这个偏差放大，所以不是越大越好。

这次改动只有 8MS.c 一个文件，四处：加了个冷却计时器 ring_cooldown，出环后 1.5 秒内不许再识别；门限 92/5 改成 80/15，消抖 4 拍改 3 拍；超时从“回状态 0”改成“跳状态 3”；出环直行 20 拍改 100 拍，结束时上冷却。

main.c、dian_gan.c、按键、电机、编码器、速度环，一个字都没动。

三条结论：

状态机的鲁棒性，一半在特征，一半在时间。入口出口磁场不可区分时，只靠空间特征的状态机一定会重复触发。

超时不是放弃，是执行降级动作。直接清零状态是最偷懒也最危险的写法。

调参要记“失败的方式”，不只是“失败的次数”。要不是盯着屏幕看那四个数，我可能会在 92 附近试一下午。
